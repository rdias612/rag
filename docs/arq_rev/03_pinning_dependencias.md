# 03 - Pinning de Dependências

## Objetivo
Garantir builds reproduzíveis com versões exatas de todas as dependências.

---

## Problema Atual

```txt
# requirements.txt atual
flask>=3.0.0          # Pode instalar 3.0, 3.1 ou 3.2
psycopg2-binary>=2.9.9
```

Isso causa:
- Builds diferentes em ambientes diferentes
- Bugs difíceis de reproduzir ("funciona na minha máquina")
- Vulnerabilidades silenciosas em updates

---

## Arquivos a Criar/Modificar

| Arquivo | Descrição |
|---------|-----------|
| `requirements/base.in` | Dependências diretas (input) |
| `requirements/base.txt` | Lock completo (gerado) |
| `requirements/dev.in` | Ferramentas de desenvolvimento |
| `requirements/dev.txt` | Lock de dev (gerado) |
| `requirements.txt` | Symlink ou referência para `requirements/base.txt` |

---

## Passos de Implementação

### Passo 1: Instalar pip-tools

```bash
pip install pip-tools
```

### Passo 2: Criar Estrutura

```bash
mkdir requirements
```

### Passo 3: Criar `requirements/base.in`

```txt
# =============================================================================
# RAG System - Base Dependencies
# =============================================================================

# Web Framework
flask
flask-cors

# Security
cryptography

# Database
psycopg2-binary
SQLAlchemy
alembic

# HTTP Client
requests

# NLP
spacy
langdetect

# Re-ranking
sentence-transformers

# Observability
prometheus-client

# Configuration
python-dotenv
pydantic
pydantic-settings

# Scheduling
apscheduler

# Document Processing
markitdown

# Production Server
gunicorn
```

### Passo 4: Criar `requirements/dev.in`

```txt
# =============================================================================
# Development Dependencies
# =============================================================================

-r base.txt  # Inclui dependências de produção

# Testing
pytest>=7.0.0
pytest-cov>=4.0.0
pytest-asyncio>=0.21.0
httpx  # Para testar endpoints

# Linting & Formatting
black>=23.0.0
isort>=5.12.0
flake8>=6.0.0
mypy>=1.0.0

# Type Stubs
types-requests
types-python-dateutil

# Debugging
ipdb
rich
```

### Passo 5: Gerar Lock Files

```bash
# Gerar base.txt (produção)
pip-compile requirements/base.in -o requirements/base.txt

# Gerar dev.txt (desenvolvimento)
pip-compile requirements/dev.in -o requirements/dev.txt
```

**Output esperado** (`requirements/base.txt`):

### Passo 6: Atualizar requirements.txt da Raiz

Opção A (arquivo de referência):
```txt
# Production dependencies - see requirements/base.txt for full lock
-r requirements/base.txt
```

Opção B (symlink no Linux/Mac):
```bash
ln -sf requirements/base.txt requirements.txt
```

### Passo 7: Adicionar ao .gitignore

```gitignore
# NÃO ignorar os .txt gerados - eles devem ser commitados
# requirements/*.txt  # ERRADO - não adicionar isso
```

---

## Workflow de Atualização

### Adicionar Nova Dependência
```bash
# 1. Adicionar ao .in
echo "redis" >> requirements/base.in

# 2. Regenerar lock
pip-compile requirements/base.in -o requirements/base.txt

# 3. Instalar
pip-sync requirements/base.txt
```

### Atualizar Todas as Dependências
```bash
pip-compile --upgrade requirements/base.in -o requirements/base.txt
```

### Atualizar Dependência Específica
```bash
pip-compile --upgrade-package flask requirements/base.in -o requirements/base.txt
```

---

## Verificação

```bash
# Instalar exatamente as versões do lock
pip-sync requirements/base.txt

# Verificar que não há diferenças
pip freeze | diff - requirements/base.txt
```

---

## Integração com CI

```yaml
# .github/workflows/ci.yml
- name: Verify dependencies are locked
  run: |
    pip-compile requirements/base.in -o /tmp/base.txt
    diff requirements/base.txt /tmp/base.txt || (echo "Lock file outdated!" && exit 1)
```
